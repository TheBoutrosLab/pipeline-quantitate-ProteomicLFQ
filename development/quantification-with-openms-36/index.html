Quantification with OpenMS 3.6

OpenMS and pyOpenMS default to version 3.6.0. The former merged and machine_learning FFId strategies and their OpenMS 3.5 processing have been retired. Set enable_mbr = true to include unidentified MS1 features in QT linking. The seed detector follows the OpenMS 3.6 LFQ settings for unlabeled FeatureFinderMultiplex. Its wrapper uses TOPP-style -in, -out, and -algorithm:charge; -threshold_mower:threshold controls the separate preprocessing step. Seeded FFId uses each run's own idXML. Its wrapper accepts the shared TOPP-style -in, -id, -out, and FFId options; -seeds is the required wrapper-specific input. Seed and quantified featureXML maps are published when save_intermediate_files = true. QT linking does not control false-transfer rate.

For fractionated cohorts, the pipeline gives each consensusXML column a unique sample-and-fraction filename and annotates its sample name, fraction number, original fraction_id, and fraction group before merging fractions. This lets OpenMS 3.6 recognize one assay per sample across all fractions. Fraction IDs in the input CSV can be text labels; the original labels remain in output filenames while OpenMS receives a positive integer fraction number assigned by each distinct label’s first appearance in the input CSV. The top-level workflow attaches the number to each input file as it reads the CSV. The linked consensusXML receives the matching number by fraction label, regardless of channel arrival order.

protein_quantifier_fractions_aggregate defaults to sum: all fractions of a sample contribute to its assay abundance. Set it to best only when one fraction per peptide should represent the sample. The separate protein_quantifier_best_charge flag (default false) selects one charge per modified peptide for protein quantification and produces detailed peptide CSV rows for each observed fraction and charge. Without it, the peptide CSV has one row per peptide with fraction set to all. The published peptide CSV renames OpenMS assay columns to abundance|<sample_name>. The detailed output from -best_charge instead uses file and channel columns. Ratio columns are no longer produced by ProteinQuantifier; calculate contrasts downstream if needed. See the OpenMS 3.6 ProteinQuantifier documentation.

OpenMS 3.6 also changed the automatic reference used by MapAlignerIdentification. This pipeline selects consensus by default to preserve its previous RT alignment behavior. The align_featureXML_id_algorithm_auto_reference parameter can override that choice.
